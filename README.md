# Held-out operand pairs in integer addition

Code and raw results for research on emergence in a small transformer: the model
is trained on integer addition `a + b` (operands 0–99, each a single token) with a
chosen share of the operand pairs **left out of training on purpose**, and held-out
accuracy is measured throughout training. Because the table of held-out pairs is
known exactly, a lookup table cannot answer them, so held-out accuracy above chance
measures a learned algorithm rather than memory.

The experiments cover how the training fraction, model width and seed decide whether
the model generalizes to the held-out pairs, how the learned embedding is structured
(Fourier analysis, causal frequency removal), and when that structure appears relative
to the accuracy jump.

**Author:** Sebastian Sonntag, GPT-Lab, Tampere University, Tampere, Finland.
A paper based on this work is in preparation; this README will link to it.

## Layout

- `koe/` – code (PyTorch). The main script is `lisays.py`; the other scripts analyse
  the logged runs. Comments and file names are partly in Finnish (`koe` = experiment,
  `tulokset` = results, `lisays` = addition, `taulukko` = table).
- `tulokset/` – logged runs (`*.csv` per-step metrics, `*.json` run summaries),
  summary tables (`taulukko_*.md`) and figures. Every number reported in the paper is
  computed from these files by a script in `koe/`. Model checkpoints (`*.pt`) are not
  included; they are regenerated by the scripts.

## Running

```
python -m venv .venv && .venv/bin/pip install -r koe/requirements.txt
cd koe
../.venv/bin/python lisays.py --frac 0.15 --seed 0 --steps 40000 --warmup 500 --clip 1.0 --out ../tulokset/ajo
```

This trains one model with 15 % of the 100×100 pairs in training and writes
`ajo.csv` and `ajo.json`. Training uses Apple MPS if available, otherwise CPU.
MPS training is not bitwise deterministic: masks are fixed by the seed, but the step at
which generalization starts varies between repeated runs.
